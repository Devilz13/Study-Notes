# Research questions: C++ Programming

## Primary question

How can a programmer decompose a problem into correct C++ control flow, functions, types, objects, resource ownership, and data structures while keeping behavior testable?

## Subquestions

- How do types, expressions, conditions, loops, and functions express an algorithm?
- When should data use arrays, vectors, strings, structures, classes, or STL containers?
- How do pointers and ownership create both flexibility and failure risk?
- When are inheritance and runtime polymorphism preferable to composition or templates?
- How do exceptions, generic programming, and algorithms change interface design?
- Which linked structure, stack, queue, recursion, or tree matches a problem's operations?

## Explicit exclusions

- Treating book examples as modern production style without compiler and guideline review
- Promoting code snippets to canonical memory without compiling and testing them
- Assuming manual memory management is preferable when standard-library ownership suffices

## Evidence needed

- `SRC-0001` for the progressive C++ curriculum and exercises
- Compiler output and reproducible tests for every code-level claim
- Current ISO C++ references and core guidelines for modern-language updates
